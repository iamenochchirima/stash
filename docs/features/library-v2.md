# Library v2

Implementation follows [the release checklist](../../LIBRARY_V2_IMPLEMENTATION.md). The goal remains active. These are local changes; production remains on the previous release until coordinated deployment.

The verified foundation adds private /items/[id] pages, card-body/title navigation, separate Open source, direct-link sign-in return, full context, editing and copy-private-link. New items include URL-free notes/ideas, safe Markdown reading, favourites, archive, 30-day Trash and restoration. The mixed-item /api/items contract and MCP tools share account ownership, revision checks and lifecycle rules. Legacy /api/resources and resource MCP tools remain link-only. New-kind capture is separately gated; linked-item reading and creation remain available during rollout.

JSON v2 preserves complete text, collections, favourites and archive/trash state; v1/bookmark imports remain available. JSON v2 also preserves extracted PDF pages and summary snapshots, with imported provenance. Data-only PDF restores show "Original not included" and disable downloads. Full ZIP export streams originals with checksums; Full ZIP restore checks every entry before import, restores originals and can repair a previous data-only import. An hourly bounded maintenance worker removes expired trash and request identities. The existing admin lifecycle and global operations still need full release regression.

Focused integration tests: tests/items.test.ts, tests/items-migration.test.ts, tests/items-portability.test.ts and the mixed-item scenario in tests/mcp.test.ts. Browser recipes: tests/browser/item-detail.spec.ts and tests/browser/items.spec.ts. Current evidence is in docs/evidence/library-v2. The browser harness uses a higher global request ceiling for aggregate rapid test traffic; individual authentication/MFA limits remain in force and the production ceiling stays unchanged.

Local PDF capture now supports 20 MiB originals, private Backblaze or local development storage, direct-to-API uploads using single-use expiring permissions, isolated bounded extraction, five-page reads, searchable text, expiring original downloads and durable deletion cleanup. Browser checks passed at 1440 and 375 pixels. A real Backblaze synthetic check verified private bucket ACL, upload, identical download and deletion of all object versions. Credentials and supplied screenshots are excluded from Git, Docker and Vercel uploads. These are local/provider checks, not hosted application acceptance.

On-demand article/PDF summaries now have explicit source disclosure, bounded source passages, saved references, source-based stale detection, durable jobs and free-only OpenRouter routing. Request aliases prevent duplicate generation across concurrent clients; quota reservations and unknown outcomes remain bounded. Failed regeneration preserves existing summaries and notes. Operational admin counts cover kinds, lifecycle states, storage, processing and usage without private content. See [summary processing](../summary-processing.md) for limits, retention and provider terms.

PDF upload details now save atomically with the original, and retrying an upload request returns its existing item. Tests cover account deletion during an in-flight upload and cleanup of the late-written original. Metadata edits during generation preserve both the new notes and a current summary.

Pending: remaining file-aware journal/recovery and hostile/concurrency checks, draft/undo refinements, final security/regression checks and coordinated deployment/hosted acceptance. Real OpenRouter PDF, article and injection cases passed at reported $0 cost. This does not prove every future model response or remove provider retention limits.


Full backup downloads use a one-use, 60-second permission tied to the current session. The direct API streams the ZIP, and a separate /backup-download/ worker forwards it to the browser download without buffering the archive or caching private bytes. Root PWA caches remain public-only. Each item/original checksum is recorded in the final manifest. Exports interrupt on changed items, unavailable accounts, invalid originals or a 15-minute limit. Two downloads may run globally and one per account. The archive reader rejects traversal, links, duplicate paths, encrypted entries, inconsistent indexes, excess entry counts/sizes, decompression beyond bounds and checksum mismatches. It reads one entry at a time from the chosen file.

Original downloads and extraction compare stored bytes with the recorded size and SHA-256 before serving/parsing. Deleted file bytes remain charged against 500 MiB account and 5 GiB global reservations until cleanup removes all remote versions. Older cleanup records reserve the maximum 20 MiB conservatively. These checks are local; production rollout remains unfinished.


Full ZIP restore now runs end to end. The browser checks all entries before offering Restore backup. Metadata and originals then go directly to the API, one bounded request at a time. The server repeats schema, identity, hash, ownership and quota checks. Existing item content is preserved; a missing original can be added without replacing later notes or imported summaries. Original adoption and extraction scheduling are atomic. A durable session records progress and source-copy references so choosing the same archive again can continue within 30 minutes, with an absolute 24-hour limit. Transient permissions rotate and old file permissions are invalidated. A different chosen archive finalises the preceding partial restore. Completed or expired restores archive only projects newly created by that restore, and leave later project edits alone. Logout immediately denies access and retains minimal bookkeeping until maintenance finalises partial archive state. Account deletion removes all records and durably schedules late-written originals for cleanup.

A real Backblaze check exported and restored a synthetic original to another disposable account, verified text and identical download bytes, checked account isolation, deleted both accounts and removed every version of both originals. Evidence: backblaze-backup-restore.json. Chromium journeys passed at 1440px and 375px with axe and overflow checks. See restore-*.txt and restored-pdf-*.png. No new AI inference calls or hosting-plan changes were needed.


Bookmark export is explicit about its scope: titles and URLs from main-library links, including archived links, with counts for excluded project, Trash and non-link items. Notes, files, summaries and organisation require JSON or a full ZIP. HTML output escapes both titles and URL attributes. Data-only JSON and bookmark downloads stream directly through the same transient download worker; JSON serialises one item at a time and bookmarks one entry at a time. Neither is cached. Legacy JSON endpoints remain compatible. Help and MCP descriptions now explain URL-free notes/ideas, scope, bounded project reads and archive/Trash defaults. Evidence: exports-mcp.txt, exports-stream.txt and exports-browser.txt.
