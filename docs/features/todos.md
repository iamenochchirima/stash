# Todos

Todos are private follow-up tasks, separate from library reading status. A task can live in the personal area or one project, belong to one named list or Inbox, and reference several saved links, notes, ideas or PDFs. Project tasks are also available from the global Todos page.

The current implementation includes Inbox, All, Today, Upcoming, Completed and Trash views; search and pagination; task title, notes, state, priority, planned date, date-only or timed deadline, subtasks and saved-source links; list creation/rename/deletion; manual task ordering; task restore and confirmed permanent deletion; project Tasks tabs; and create-task links from saved items. HTTP and MCP share account-owned services, revision checks, retry-safe request IDs and bulk move/completion/Trash actions. Read-only agent keys cannot mutate tasks.

Recurrence supports daily, weekly and monthly schedules, selected weekdays, finite count/date limits, completion history, next-occurrence creation, stopping, and safe undo only while the generated task is untouched. Reminders are durable records with in-app delivery, snooze/read/dismiss actions and optional email delivery. Email reminders require a verified address and explicit preference; messages link to the private task without including its title, notes or research. The worker suppresses reminders for ineligible tasks and retries email delivery with bounded attempts and a stable delivery key. SMTP transports may not guarantee provider-side deduplication. Permanently purging a saved source leaves its task association intact with an unavailable-source state. Task changes also update the owning project’s activity time, including both projects when a task moves, without changing project metadata revisions.

New users get their browser timezone on first Todos setup; a saved IANA timezone controls date boundaries and the default timezone for new tasks. Changing that preference does not rewrite existing task deadlines. Local verification includes PostgreSQL service/API/MCP/reminder and timezone/DST tests, desktop/mobile browser journeys with axe and overflow checks, JSON/ZIP backup round trips, account deletion/suspension, reminder lease recovery, sign-in return-path coverage, typecheck and production builds. The feature is still in progress and has not been released. Hosted acceptance and remaining rollout checklist items are tracked in the [Linear implementation checklist](https://linear.app/kasitek/document/todos-implementation-plan-and-acceptance-checklist-2294b124b9cf).

Data-only JSON v4 and full ZIP v4 exports include lists, tasks, source links, subtasks, recurrence history, reminder records and Todo preferences. Restoring into an account preserves its existing edits and maps imported IDs per owner. Pending reminder schedules remain paused after import. Older JSON and ZIP formats remain supported.
